# DNPR preview prototype

`dnpr-test` is the first, userspace phase of DNPR. It does **not** trigger or simulate a kernel panic. It renders the user-provided SuperGodot64 head geometry and game-over animation with a software depth buffer, Gouraud lighting, a tiled background, two spinning star sprites (one silver, one red), animated gold sparkles around the silver star, small animated red sparkles around the red star, and a flickering reboot prompt at the lower left. The prompt stacks `REBOOT`, `YOUR`, and `DEVICE` beside Mario, with the silver star underneath, following the supplied placement reference. It uses the SuperGodot64 colorful title glyph textures, sharing the V tile for U. Displays at 720p and above use a 128×128 atlas baked from the HD source; lower resolutions use a 16×16 atlas. Diffuse colour remains bright; interpolated normals add a separate reflective highlight. `export_head.py` bakes 131 posed frames from the local JSON into `mario_head.bin`. Playback drives the head from elapsed time like the kernel does: while the animation runs, each vsync tick blends the vertex positions between the adjacent baked poses around the current pose clock and recomputes the smooth normals from the blended surface, so a 60 Hz panel sees 60 unique head frames per second and a 144 Hz panel sees 144; when rendering falls behind, the pose clock skips source poses the same way the panic draw does. The star, sparkle, and prompt overlays keep their own clocks. Playback freezes on the half-lidded sigh pose at zero-based frame 130; stars and particles keep moving. `export_scene.py` bakes the four original game-over background strips, 16 star frames, both prompt atlases, and six sparkle frames. `export_audio.py` captures the local ROM's game-over phrase and Mario's voice through the same endpoint. The audio continues after the pose freezes and ends at the near-silent break just before the title phrase. These game-derived assets should remain local unless their distribution rights are established.

## Build and run

```sh
make
./dnpr-test --displays
./dnpr-test
./dnpr-test --no-audio
./dnpr-test --static
./dnpr-test --animation
./dnpr-test --status
./dnpr-test --stop
```

The build needs Python 3 with NumPy and Pillow, SDL2 development files, the SuperGodot64 head and texture files, its local ROM, and its local `libsm64.so` mixer. Set `SUPERGODOT64_ROOT=/path/to/SuperGodot64` when the reference project is elsewhere. The generated game assets and preview binaries are intentionally excluded from this repository.

Audio is on by default; `--no-audio` disables it. Escape also exits. `--render-frame preview.ppm` writes a headless 1920×1080 still image of the full scene; `--render-base-frame base.ppm` writes the same pose without the star, sparkle, and prompt overlays, which is the base the kernel panic asset bakes; `--frame N` selects a baked frame for inspection. The live preview renders directly to the Acer's native mode. `--display N` is accepted only when SDL and the display EDID identify that display as Acer. The current machine's Acer X233H is DVI-D-1, SDL display 0; the Microstep MP242 is HDMI-A-1, SDL display 1. If the Acer cannot be identified, fullscreen startup fails closed.

The background keeps its stretched 16:9 tile geometry and repeats additional tiles on wider screens. Sparkles use 128×128 HD frames at 720p and above and 32×32 SD frames below 720p.

The preview uses SDL's compositor-managed fullscreen desktop window. Hyprland retains DRM master and the display mode. The live preview rasterizes into a RAM image, bulk-copies that image to a CPU-mappable DRM dumb buffer, and presents the RAM image through an SDL window surface on the Acer. It does not create an SDL renderer or streaming texture. Direct rasterization into the mapped NVIDIA buffer followed by SDL readback was measured at roughly 0.01 fps; the panic path never reads scanout back. If a mapped DRM buffer is unavailable, it logs the fallback and presents the RAM image. `--no-drm-buffer` disables the extra DRM copy for a baseline. The dumb buffer is linear and is not the proprietary driver's block-linear panic scanout, so preview FPS is not a kernel panic FPS measurement. Closing the window restores the prior desktop state without changing connector routing. The control socket lives at `$XDG_RUNTIME_DIR/dnpr-test-UID.sock`; a stale socket is replaced only after a failed connection. A process crash closes its Wayland window, so it cannot retain display ownership. Rasterization runs on persistent worker threads created once at startup; each frame the workers and the calling thread grab 32-row bands from an atomic queue, so rows never straddle threads and the depth buffer needs no locking. Threads are only used in the SDL preview; the panic renderer still draws on one CPU.

## Verified on this system

- Kernel: Linux 6.15.2, `CONFIG_DRM_PANIC=y`.
- GPU: GTX 1060 bound to proprietary `nvidia` 575.57.08 modules.
- Desktop: Hyprland on Wayland. Acer X233H: 1920×1080 at 60 Hz, DVI-D-1. Microstep MP242: 1920×1080 at 144 Hz, HDMI-A-1.
- SDL enumerated and identified both displays. Hyprland reported the DNPR fullscreen window on monitor 0 (Acer), workspace 2.
- Static preview, animation, audio, status, and stop completed. PipeWire showed a 32 kHz stereo playback stream. A comparison against music-only capture confirmed Mario's voice signal from about 0.5 to 1.5 seconds. The audio ends at 6 seconds with a quarter-second fade over the natural break. The rebuilt audio preview ran on Acer monitor 0 and stopped cleanly. After exit, no DNPR window remained, and both displays retained their modes and workspaces.
- Native-resolution frame generation and build completed without warnings.
- At 1920×1080, a local render benchmark measured about 23.5 ms per changing head pose on one thread. The rasterizer now splits the frame into 32-row bands pulled from an atomic queue by persistent worker threads plus the calling thread, one worker per logical CPU up to 15. On this machine (6 cores, Hyper-Threading, 12 hardware threads) that measures about 5.0 ms per changing pose, a 4.7× speedup, and the 1.1 ms frozen-frame path after caching the completed head image is unchanged. Renders at poses 0, 60, and 130 are bit-identical to the single-threaded build because each row is rasterized exactly once with the same math. A separate 640×360 render verified the low-resolution atlas path.
- Interpolated playback was verified headless: a frac=0 blend reproduces the baked pose bit-for-bit, a frac=0.5 blend lands on the vertex midpoints with unit-length recomputed normals, renders of poses 60, 60.5, and 61 are three distinct images, and the frozen hold after the animation is stable across ticks. The `--frame N` inspection path still renders the exact baked pose.
- Kernel #44: a real panic displayed the shared animated scene on both scanouts and played Mario's game-over cue through the Microstep HDMI, bypassing PipeWire. The audio fix was the raw-deflate blob change; the panic path itself needed no change.
- The preview reads 644 posed 3D vertices and rasterizes 1,213 triangles per frame, with a depth buffer and live SDL audio. Headless renders of poses 0 and 60 have different hashes. This verifies the preview path; it does not verify a kernel panic.

## Kernel panic backend

`kernel/dnpr-linux-6.15.2.patch` adds a `CONFIG_DRM_DNPR` panic screen to Linux 6.15.2. A phone video of kernel build #35 showed Mario animate, but the scene restarted on the second monitor because each DRM plane ran its own sequence. Build #41 collects both scanouts before starting one shared animation clock. Both connected outputs report 1920×1080; a preallocated 1080p frame is composed once, then copied to each scanout. Other output sizes use the direct compositor. Mario's 131 posed vertex frames play once and then hold the final sigh. The panic draw has a 144 Hz ceiling and uses elapsed time: when rendering is below 30 fps it skips source poses, and above 30 fps it interpolates between adjacent poses. The 3D scene is rasterized in software into the shared frame. After Mario reaches the final sigh, draws slow to the 12 fps texture clock. Star and particle textures advance on that clock; `REBOOT YOUR DEVICE` changes visibility every 15 original game frames (500 ms). During Mario's animation, the renderer updates the old and new head bounds plus the star and prompt regions. After the head settles, it updates only the star and prompt regions. The small magenta frame counter remains visible as requested; the preview draws the same counter in its live window. The audio source prepares the six-second cue as HDA DMA buffers at boot, then takes over one NVIDIA HDA output stream and routes it to the connected Microstep HDMI codec when the panic starts. It is enabled by default and bypasses PipeWire and sleeping ALSA calls in the panic path. Build #42 reduced per-pixel shading math but changed the visible gloss. Build #43 restores the original shading calculation, scans only conservative triangle spans instead of their full bounding boxes, and skips unchanged pixels in block-linear scanouts. Emit raw deflate from the export script instead, matching the helper's contract, and add stage-wise failure logging to `dnpr_hda_init`. Build #44 fixes the panic audio: `export_panic_audio.py` embedded a zlib-wrapped stream, but the kernel's `zlib_inflate_blob` helper expects raw deflate, so the boot-time decode failed, the module logged `panic HDA PCM unavailable`, and the panic draw ran with no audio at all. After installing #44, a real panic on this machine displayed the animated scene and played the six-second cue through the connected Microstep HDMI as intended. Build #45 added a 32-row SMP queue and a boot-time CRC selftest. That selftest runs while other CPUs are online and confirmed the band renderer, but the normal panic path stops other CPUs before DRM invokes DNPR. The panic-time helper IPIs therefore cannot run. On this x86 kernel, stopped CPUs are also removed from the online mask, so helper startup returned without dispatching work; it did not add a 25 ms wait. Build #47 removes that dead call but is not expected to change FPS. The SMP selftest remains available at boot. Build #48 replaces the seven signed 64-bit divisions per visible head pixel with exact invariant-divisor quotients: one reciprocal is prepared per triangle, then a high-half multiply and one correction reproduce truncating division. The depth, diffuse colours, normals, and gloss formula retain their exact integer results. A focused 8.5-million-quotient benchmark took 43.4 ms with division and 8.6 ms with the exact reciprocal method on this machine. Panic FPS for #48 still needs a quantified recording. The next source change preloads a 16 MiB exact lookup for the integer gloss function from a 96 KiB deflate blob; it removes the per-pixel square root and normal-length division while matching the corrected signed gloss formula for all 8-bit normal triples. The old unsigned length divisor accidentally made negative light dots produce a bright highlight; the fallback now uses signed division too. If that allocation fails, the corrected arithmetic runs. A standalone 3-million-sample gloss benchmark took 33.75 ms arithmetically and 9.35 ms through the lookup. These are component timings, not a measured panic FPS increase. This is kernel build #49, installed at `/boot/vmlinuz-6.15.2-dnpr` with a matching System.map; the running kernel remains #48 until reboot. The previous image is backed up at `/mnt/nvme/vmlinuz-6.15.2-dnpr.pre-spec-lut`. HDA DMA plays audio independently; the panic CPU checks its stop point. Build #46 attempts to stop the panic audio cleanly: the HDA controller runs the BDL cyclically, so a panic played the six-second cue and then wrapped to entry 0 and replayed into the cue's loud opening until the stop check noticed, which the 12 fps ambient tick plus per-tick render work made late enough to hear. `dnpr_audio_maybe_stop` now repoints every BDL entry the DMA has finished with at a page of silence as it goes, so a wrap should replay silence, and requests a stop at 5.9 s. Local PCM inspection found samples through 5.94 s, but peak amplitude falls to 1 after 5.9 s and zero by 5.95 s. This change is compiled into the installed #47 image but has not been verified by a panic recording after reboot. `dnpr_audio_start` rebuilds the cue's BDL, so a second start in one boot plays the cue again.

To build the experimental kernel source from this repository, run `make kernel-assets` with your own local game assets. This creates `kernel/dnpr_frame_blob.h`, `kernel/dnpr_live_blob.h`, and `kernel/dnpr_audio_blob.h`; all are excluded from Git because they contain game-derived data. Apply the patch to a matching Linux 6.15.2 tree, copy the DNPR C files, headers, and generated blobs from `kernel/` into `drivers/gpu/drm/`, enable `CONFIG_DRM_DNPR=y`, and rebuild the kernel and modules.

The Linux 6.15.2 DRM panic implementation requires the primary plane's `get_scanout_buffer` helper. Upstream NVIDIA 575.57.08 does not provide it. `kernel/nvidia-drm-panic.patch` adds that hook and a block-linear pixel writer. Phone video confirms panic display on this machine; performance and behavior may differ on other GPUs.

**Rebuild external GPU modules for the new kernel release** so normal desktop graphics can load. This alone only matches the kernel ABI; a panic display also needs a working scanout hook in the GPU module. This machine reuses `initramfs-linux.img`. It contains older kernel modules that cannot load into `6.15.2-dnpr`, but root storage and filesystem support are built into the kernel and matching NVIDIA modules live on the root filesystem. The machine has now booted `6.15.2-dnpr` with the reused initramfs and loaded the matching NVIDIA modules.

The installed #48 kernel is `/boot/vmlinuz-6.15.2-dnpr`; the previous #47 image is backed up at `/mnt/nvme/vmlinuz-6.15.2-dnpr.pre-exact-div`, #46 at `/mnt/nvme/vmlinuz-6.15.2-dnpr.pre-smp-fix`, #45 at `/mnt/nvme/vmlinuz-6.15.2-dnpr.pre-audio-stop`, #44 at `/mnt/nvme/vmlinuz-6.15.2-dnpr.pre-smp`, #43 at `/mnt/nvme/vmlinuz-6.15.2-dnpr.pre-audio-fix`, #42 at `/mnt/nvme/vmlinuz-6.15.2-dnpr.pre-span-opt`, #41 at `/mnt/nvme/vmlinuz-6.15.2-dnpr.pre-raster-opt`, #39 at `/mnt/nvme/vmlinuz-6.15.2-dnpr.pre-delta`, #38 at `/mnt/nvme/vmlinuz-6.15.2-dnpr.pre-paced`, #36 at `/mnt/nvme/vmlinuz-6.15.2-dnpr.pre-shared`, #35 at `/mnt/nvme/vmlinuz-6.15.2-dnpr.pre-sync`, #33 at `/mnt/nvme/vmlinuz-6.15.2-dnpr.pre-direct-loop`, the live-3D-only image at `/mnt/nvme/vmlinuz-6.15.2-dnpr.pre-audio`, and the older static image at `/mnt/nvme/vmlinuz-6.15.2-dnpr.pre-live3d`.
